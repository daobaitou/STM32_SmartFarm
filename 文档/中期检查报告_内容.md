## 一、毕业设计（论文）的主要内容

设计并实现一套基于STM32的智能农业监测与灌溉控制系统，涵盖嵌入式终端、云端通信和远程上位机三个层面：

（1）**硬件系统设计**：以STM32F103C8T6微控制器为核心，集成DHT22空气温湿度、FC28土壤湿度、DS18B20土壤温度、BH1750光照强度、BMP180大气压强等多传感器采集模块，通过ESP8266 WiFi模块接入MQTT协议实现设备上云，配合继电器驱动水泵执行灌溉动作，OLED显示屏实现现场数据展示。

（2）**嵌入式软件设计**：基于FreeRTOS实时操作系统进行多任务并发开发，包括传感器采集任务、MQTT通信任务、OLED显示任务、灌溉控制任务等，通过消息队列实现任务间数据共享。

（3）**远程监控平台设计**：开发基于QT框架的桌面端上位机和基于Flask的Web端，实现传感器数据实时展示、历史曲线绘制、灌溉模式切换等功能。云端采用腾讯云服务器部署Mosquitto MQTT Broker。

### 2.1 已完成的研究内容及阶段性成果

#### （1）传感器驱动开发（Phase 1，已完成）

完成了7个传感器/外设模块的驱动开发，所有驱动均在裸机环境下独立测试通过：

| 模块 | 型号 | 接口 | 引脚 | 测试结果 |
|------|------|------|------|----------|
| 空气温湿度 | DHT22 | 单总线 | PA1 | 驱动完成，硬件待修（缺上拉电阻） |
| 土壤温度 | DS18B20 | 单总线 | PA6 | ✓ 稳定读取25.0~25.1°C |
| 土壤湿度 | FC28 | ADC | PA0 | ✓ ADC值正常，线性映射0~100% |
| 光照强度 | BH1750 | 软件I2C | PB6/PB7 | ✓ 稳定读取光照值 |
| 大气压强 | BMP180 | 软件I2C | PB6/PB7 | ✓ 稳定读取气压值 |
| 水流检测 | YF-S201 | EXTI中断 | PB0 | 驱动完成，硬件接线待查 |
| OLED显示 | SSD1306 | 软件I2C | PB6/PB7 | ✓ 128×64正常显示 |

在驱动开发过程中，解决了多项关键技术难题：
- **DS18B20时序问题**：HAL库GPIO切换过慢（数十微秒），超出1-Wire协议时序窗口。解决方案为直接操作GPIO寄存器（CRL），配合DWT周期计数器实现微秒级精确延时，经过6次以上重写最终稳定。
- **I2C总线死锁**：STM32F103硬件I2C存在硅片级缺陷（官方Errata记载），OLED与BH1750共用总线时偶发死锁导致系统卡死。解决方案为编写GPIO模拟I2C驱动，完全绕开硬件I2C外设，采用开漏输出+关中断保护时序，50kHz时钟速率，系统彻底消除I2C死锁问题。

#### （2）FreeRTOS多任务架构（Phase 2，已完成）

成功移植FreeRTOS V202411.00，设计并实现了6个并发任务：

| 任务 | 优先级 | 栈大小 | 功能 |
|------|--------|--------|------|
| Sensor | 3 | 512字 | 周期采集7个传感器数据，发送到消息队列 |
| LCD | 2 | 384字 | 从队列读取数据，刷新OLED显示 |
| Print | 2 | 192字 | 串口打印传感器数据（调试用） |
| LED | 0 | 128字 | 板载LED状态指示 |
| MQTT_Pub | 2 | 512字 | 传感器数据JSON格式化，发布到MQTT Broker |
| MQTT_Sub | 4 | 256字 | 订阅控制主题，接收远程命令 |

任务间通信机制：
- **xQueue_SensorData**（长度3）：传感器数据广播队列，采用发送3份副本实现多消费者共享
- **xQueue_ControlCmd**（长度4）：控制命令队列，MQTT订阅任务 → 灌溉控制任务
- **xMutex_I2C**：I2C总线互斥锁，防止多任务同时操作OLED
- **xMutex_USART2**：USART2互斥锁，防止MQTT_Pub和MQTT_Sub并发冲突

关键解决方案：
- 重写HAL_InitTick()，将HAL时基从SysTick迁移到TIM4，SysTick完全留给FreeRTOS内核
- 修正configMAX_SYSCALL_INTERRUPT_PRIORITY配置，从错误值11修正为(5<<4)=80，解决Hard Fault
- 多次调整任务栈大小（printf需300+字节栈空间），最终消除栈溢出导致的系统崩溃

#### （3）ESP8266 MQTT通信集成（Phase 2，已完成）

完成了嵌入式终端到云端的完整通信链路：

**硬件层**：ESP-12E (NodeMCU) 通过USART2（PA2/PA3）与STM32通信，AT UART映射到GPIO15/GPIO13（D8/D7引脚），避开NodeMCU板载CH340对GPIO1/GPIO3的占用。

**驱动层**：
- usart2_driver：512字节环形缓冲区 + RX中断驱动的非阻塞UART驱动
- esp8266_at：AT命令封装，支持WiFi连接、TCP连接、数据收发，所有操作受互斥锁保护
- esp_mqtt：MQTT 3.1.1协议手动编码，支持CONNECT/PUBLISH/SUBSCRIBE/PINGREQ操作

**MQTT通信**：
- Broker地址：124.223.5.91:1883（腾讯云Mosquitto）
- 上行主题：`smartfarm/farm_001/sensor/data`（传感器JSON数据）
- 下行主题：`smartfarm/farm_001/control/mode`、`control/pump`、`config/threshold`
- 传感器数据以JSON格式发布，包含温度、湿度、土壤湿度、光照、气压等字段

由于ESP-AT固件MQTT命令不可用（SET操作返回ERROR），采用原始TCP连接+手动编码MQTT 3.1.1协议数据包的方式绕过，经Python脚本验证MQTT CONNECT/PUBLISH协议正确性后集成到STM32。

#### （4）数据存储（已完成）

集成W25Q64 SPI Flash存储模块（2MB），实现系统配置参数的持久化存储，包括土壤湿度阈值、灌溉模式等关键参数。

## 三、目前存在的或预期可能出现的问题，拟采用的解决方案

### 3.1 当前存在的问题

**（1）DHT22温湿度传感器读取失败**

问题：DHT22始终返回读取失败，温度和湿度值为异常。

原因：单总线缺少外部上拉电阻，信号线电平不稳定，无法完成通信握手。

解决方案：在DHT22数据线（PA1）与VCC之间添加4.7KΩ上拉电阻，预计可解决。

**（2）YF-S201水流传感器脉冲计数为零**

问题：EXTI0中断始终未触发，脉冲计数为0。

原因：硬件接线未确认，可能未正确供电（需5V）或信号线未连接到PB0。

解决方案：检查硬件接线（红线→5V，黑线→GND，信号线→PB0），用吹气或拨动叶轮验证脉冲产生。

**（3）ESP8266 WiFi连接间歇性失败**

问题：WiFi热点"KmustAuto"连接偶尔超时，重试后可恢复。

原因：WiFi热点信号不稳定或ESP8266启动时间不足。

解决方案：已实现10次重试机制，后续可增加信号强度检测和自动重连逻辑。

### 3.2 预期可能出现的问题

**（1）RAM资源紧张**

STM32F103C8T6仅20KB RAM，当前FreeRTOS堆占用约12KB，6个任务栈+缓冲区+队列约10KB，剩余空间有限。后续新增灌溉控制、报警等任务时可能内存不足。

解决方案：进一步优化缓冲区大小，合并低优先级任务，必要时裁剪printf输出。

**（2）MQTT通信稳定性**

当前使用原始TCP+手动MQTT编码，未实现完整的MQTT QoS 1重传机制，网络不稳定时可能丢失数据。

解决方案：为控制命令（下行）增加应用层确认机制，传感器数据（上行）允许偶发丢失。
